## Сценарий на четыре минуты

1. **0:00–0:35.** На экране «Учебный планировщик» выбрать «Нурболат Арайлым». Показать ближайший дедлайн и счётчик просроченных. Назвать правило: сегодня ещё можно сдать, а прошедший срок имеет значение только для незавершённой задачи.
2. **0:35–1:20.** Раскрыть «Добавить задачу». Ввести **Сдать отчёт по базам данных**, выбрать «Базы данных», срок завтра, высокий приоритет и статус «В работе». Нажать «Создать задачу». Записать ID из зелёного сообщения — он понадобится в конце.
3. **1:20–1:55.** Ввести «отчёт» в поиск, выбрать дисциплину «Базы данных». В таблице найти записанный ID. В списке «Выберите задачу» выбрать ту же запись. Фильтр статуса оставить «Все статусы», чтобы видеть результат отметки о выполнении.
4. **1:55–2:35.** В «Редактировать задачу» перенести срок на неделю вперёд и сохранить. Показать новый срок, прежний ID и название. В Swagger можно выполнить GET по этому ID и показать `due_date`.
5. **2:35–3:10.** Нажать «Отметить выполнение». Показать статус «Выполнена» в таблице и изменение счётчика открытых задач.
6. **3:10–4:00.** Раскрыть «Удалить задачу», поставить подтверждение с её номером и нажать «Удалить окончательно». В Swagger открыть `GET /tasks/{id}`, нажать **Try it out**, подставить записанный ID и нажать **Execute**. Показать **404** и сообщение «Задача с таким ID не найдена.».

## Карта кода и путь одной задачи

| Файл | Что в нём искать |
|---|---|
| `app/frontend/ui.py` | Экран, фильтры, формы, HTTP-клиент, пересчёт сроков |
| `app/main.py` | Объект FastAPI, запуск посева при старте и подключение роутера |
| `app/routers/tasks.py` | Маршруты справочников и задач, SQL-запросы и ответы 404 |
| `app/schemas.py` | Контракты создания, частичного изменения и чтения |
| `app/database/models.py` | Таблицы, ключи, связи и допустимые значения статуса и приоритета |
| `app/database/db.py` | Адрес SQLite, движок, создание таблиц, сессия на запрос |
| `seed.py` | Первый набор данных и защита пользовательских изменений при повторном запуске |

| `requirements.txt`, `requirements/` | Общая установка для ноутбука и отдельные зависимости сервисов |
| `Dockerfile`, `Dockerfile.frontend`, `docker-compose.yml` | Два образа, сеть, порядок запуска и постоянный том |

**Путь записи.** Когда Арайлым нажимает «Создать задачу», `task_form` собирает значения, а `api` отправляет их в JSON-теле HTTP-запроса `POST /tasks`. FastAPI передаёт данные схеме `TaskCreate`. Обработчик `create_task` проверяет внешние ключи и создаёт объект SQLModel. Сессия при `commit()` записывает строку в SQLite, а `refresh()` перечитывает выданный ID. FastAPI возвращает 201 и объект по схеме `TaskRead`. Функция `saved` вызывает `st.rerun()`, интерфейс повторяет GET с текущими фильтрами и строит новую таблицу.

## Ответы на контрольные вопросы

### ЛР 1. Окружение и Git

1. **Зачем venv?** В `.venv` лежат интерпретатор окружения и библиотеки этого проекта. При общей установке обновление пакета для другой работы может нарушить совместимость.
2. **Что делает .gitignore?** Git пропускает новые файлы, подходящие под правила. Окружение можно восстановить по requirements, локальная база содержит меняющиеся задания, а `.env` может содержать пароль. Уже отслеживаемые файлы правило само из истории не удаляет.
3. **Как помогает ИИ?** Codex подготовил каркас, запросы и тесты. Сгенерированный код проверяют запуском и чтением: например, тест частичного обновления проверяет, что перенос срока сохранил название.
4. **Зачем ветки?** Ветка — имя линии коммитов. `git switch -c feature/search` создаёт ветку и переключает на неё. В командном проекте защищённая main позволяет проверить изменения до слияния.
5. **Чем отличаются commit и push?** Commit сохраняет снимок подготовленных файлов в локальном `.git`. Push передаёт коммиты в удалённый репозиторий и обновляет его ветку. Один push может передать несколько коммитов.

### ЛР 2. Данные и ORM

1. **Что такое ORM?** Она сопоставляет Python-классы и таблицы. `Task` описывает форму записи в коде, объект представляет одну задачу в памяти, а строка таблицы `task` хранится в файле SQLite после фиксации транзакции.
2. **Чем отличаются внешний ключ и Relationship?** `task.student_id` — число в столбце, ссылающееся на `student.id`. `task.student` позволяет в Python получить связанный объект. `student.tasks` ведёт в обратную сторону. SQLModel связывает эти свойства через `back_populates`.
3. **Зачем посев?** Пять демозадач позволяют сразу увидеть разные статусы, сроки и фильтры. Если студенты уже существуют, `seed_demo` завершает работу, поэтому удалённая задача не появляется снова.
4. **Что даёт echo=True?** Движок печатает SQL. Можно увидеть, как Python-запрос превращается в SELECT или INSERT. В проекте это включает переменная `SQL_ECHO=1`.
5. **Почему models.py в Git, а database.db исключена?** По коду моделей и seed любой участник может создать базу. Данные каждого студента меняются локально. Двоичный файл базы трудно сравнивать и объединять при работе в Git.

### ЛР 3. API

1. **Что такое REST API?** Клиент обращается к ресурсам по URL. GET читает задачу или список, POST на `/tasks` создаёт запись и возвращает её ID.
2. **Что проверяет Pydantic?** Схема проверяет тип даты, допустимый статус, обязательные поля и название после удаления крайних пробелов. Существование студента и дисциплины обработчик проверяет отдельным запросом.
3. **Зачем Depends?** Перед вызовом маршрута FastAPI получает сессию из `get_session`. Контекстный менеджер закрывает её после запроса. Общая сессия для параллельных запросов смешивала бы состояние транзакций.
4. **Откуда берётся Swagger?** FastAPI собирает описание OpenAPI из путей, аннотаций и схем. На `/docs` Swagger UI строит формы по `/openapi.json`. JavaScript и стили интерфейса поставляются вместе с зависимостями проекта.
5. **Когда вернётся 422?** Когда смысл или формат данных расходится со схемой. Примеры — пустое название, неверная дата или отсутствующий ID дисциплины при создании.

### ЛР 4. Изменение и поиск

1. **PUT или PATCH?** PUT обычно заменяет представление ресурса целиком. PATCH передаёт выбранные изменения. Для переноса дедлайна достаточно `{"due_date":"2026-12-08"}`, поэтому объём данных меньше.
2. **Где query-параметры?** После знака вопроса в URL, например `/tasks?student_id=1&subject_id=1`. Сервер добавляет условия `where` к выборке до чтения строк.
3. **Как обрабатывается None?** `exclude_unset=True` отбрасывает пропущенные поля. Явный JSON `null` проверяет валидатор `reject_explicit_nulls` и возвращается 422. Так можно отличить пропуск от попытки стереть обязательное значение.
4. **Зачем искать ID перед удалением?** `find_task` возвращает найденный объект для `session.delete`. Если строки уже нет, клиент получает конкретный 404. Это удобно и при повторном нажатии.
5. **Что входит в CRUD?** Create — POST, Read — GET, Update — PATCH или PUT, Delete — DELETE. В проекте обновление частичное.

### ЛР 5. Интерфейс

1. **Как общаются компоненты?** Streamlit выполняет Python-код на стороне своего сервера и обращается к FastAPI по HTTP. Ответы со списками и созданными задачами передаются в JSON.
2. **Что делают requests, params и json?** Requests отправляет HTTP-запрос. `params` помещает фильтры в URL у GET. `json` сериализует поля формы в тело POST или PATCH.
3. **Что увидит студент при остановке API?** Интерфейс поймает ошибку соединения или тайм-аут, покажет сообщение о недоступности сервера и кнопку повтора. После запуска Uvicorn можно повторить загрузку.
4. **Почему скрипт выполняется снова?** При изменении виджета Streamlit получает новое состояние и запускает скрипт сверху вниз. Поля внутри формы отправляются вместе кнопкой. После записи приложение вызывает `st.rerun()`, чтобы таблица перечиталась из API.
5. **Когда удобен Streamlit?** Форму, таблицу и выбор даты можно собрать на Python в одном модуле. При детальной настройке браузерных событий или произвольной верстке нужны дополнительные компоненты. Для поиска при наборе здесь используется компонент с небольшой задержкой.

### ЛР 6. Docker

1. **Контейнер и виртуальная машина.** Контейнер изолирует процессы и зависимости, используя ядро среды контейнеров. ВМ запускает отдельную гостевую ОС со своим ядром. Docker Desktop на Windows предоставляет Linux-среду для наших образов.
2. **Как читать Dockerfile?** `WORKDIR` задаёт рабочую папку, `COPY` добавляет файлы, `RUN` устанавливает библиотеки во время сборки, `EXPOSE` указывает порт приложения, `CMD` задаёт команду при старте. Порт для браузера публикует секция `ports` в Compose.
3. **Зачем .dockerignore?** Она исключает лишнее из контекста сборки. Windows-окружение venv увеличило бы размер передаваемых файлов, а его программы рассчитаны на другую ОС.
4. **Почему backend:8000?** Встроенный DNS Docker в сети Compose разрешает имя сервиса `backend` в адрес его контейнера. Для процесса во frontend адрес localhost ведёт в сам frontend. Браузер на Windows попадает к сервисам через опубликованные порты localhost.
5. **Что происходит при down?** Удаляются контейнеры и их изменяемые слои. Файл в `/data` лежит на отдельном именованном томе, который обычная команда down сохраняет. Следующий up подключает его снова.

### ЛР 7. Тестирование

1. **Зачем автоматические тесты?** Модульный тест проверяет небольшую часть логики, интеграционный — работу частей вместе. Здесь один запрос проходит через FastAPI, проверку полей и настоящую временную SQLite. Повторить все варианты вручную при каждом изменении дольше.
2. **Нужен ли Uvicorn для TestClient?** Нет. TestClient вызывает приложение внутри процесса. Конструкция `with TestClient(app)` также запускает обработчик старта для тестовой базы.
3. **Что делает httpx?** Он предоставляет HTTP-клиент, на котором построен TestClient. В тестах доступны привычные `get`, `post`, `status_code` и `json()`. Для асинхронных тестов у httpx есть AsyncClient.
4. **Чем помогает ИИ при ревью?** Он быстро предлагает граничные случаи. В этом проекте проверяются явный null в PATCH, отсутствующие ссылки и кириллица в поиске. Решение проверяется сопоставлением с требованиями и выполнением теста.
5. **Что такое регрессионный тест?** Это повторяемая проверка уже работающего поведения. Если изменение фильтрации начнёт возвращать задачи других студентов, `test_combined_filters` обнаружит лишнюю строку.
